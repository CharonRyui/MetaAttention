# Compile stateful programs compositionally

Stateful Operator will lower validated Algorithm IR through one compositional compiler pipeline: compiler-owned typed algebra classifies programs as scanable or recurrent, derives Backward IR from node VJPs, and assembles parallel chunked TileLang kernels from node semantics. The H20-first implementation will support Gated Linear Attention, RetNet recurrent, Mamba2, and GDN without model-name dispatch, whole-algorithm execution bypasses, eager recurrence, or specialized kernels; IR-generic canonicalization, fusion, layout, and schedule optimization remain allowed. Mathematically valid recurrent programs are rejected before backend lowering, while scanable programs support initial and final state plus cotangents through output, final state, and initial state. `analyze_program` performs code-generation-free analysis against an explicit immutable `Target`; `StatefulOperator` requires the same Target and consumes that analysis.

## Considered Options

A growing catalog of whole-graph templates was rejected because unseen compositions would require new patterns. A generic sequential GPU recurrence was rejected because parallel chunked execution is part of the interface. Specialized FlashQLA/GDN execution was rejected because it would preserve a second semantic path rather than exercising the compositional compiler.

## Consequences

The change lands only as an end-to-end strict cutover: no default Target, legacy Constant form, compatibility alias, or partially switched execution path remains. The first implementation and public Stateful Operator capability target H20 architecture only; runtime tensors must match before cache lookup or code generation. Gated Linear Attention, RetNet recurrent, Mamba2, and GDN require correctness and performance baselines there, while other architectures are rejected explicitly. The cutover removes `GDNEngine` and migrates all exports, documentation, tests, and repository callers; GDN remains demonstrated through explicit IR construction in `examples/`. `LinearAttentionEngine` remains an unchanged legacy entry with implicit device behavior outside the new compiler guarantee; shared low-level lowering logic may evolve without routing it through Stateful Operator. Mamba2 is corrected to use its selective diagonal transition while preserving its example factory contract. Algorithm IR will eventually carry one transition per named state and add dedicated compiler-known multi-state readout nodes, but the first implementation stages this behind the current single-state profiles. Constants become explicitly typed, state and cotangent computation obey declared accumulation dtype, Head Mapping owns grouped-head VJP reductions, aliased Tensor Input bindings accumulate gradients correctly, and cache identity includes an explicit compiler schema version. Existing performance is measured with the repository benchmark methodology on an idle H20 before cutover; any statistically significant median-latency regression blocks merge pending explicit review rather than an unspecified automatic tolerance. This ADR becomes accepted only after CPU analysis/VJP evidence and one generic parallel H20 kernel profile satisfy correctness and baseline review.
